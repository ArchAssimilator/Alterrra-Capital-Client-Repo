# Reusable Prompt: Market Entry P&L Driver Tree Generator With Stateful Logic

---

I am going to give you a description of a business, product, and target country or market. Your task is to produce a **colour-coded, interactive HTML market-entry P&L driver tree** for that situation. The HTML file must be both:
- a human-viewable tree
- a machine-readable spec for a downstream Excel model

This version explicitly supports **stateful monthly logic** for nodes whose value in month `n` depends on month `n-1`.

The output must remain compatible with the downstream schema defined below.

---

### WHAT THE TREE REPRESENTS

The tree is a full decomposition of:

```text
Net Profit = Revenue − Total Costs
```

Every node is either:
- A **calculated node**
- An **input node**
- A **reference node**

For market-entry cases, the revenue branch may be driven by:
- market size
- reachable population
- region mix
- channel mix
- provider onboarding
- funded access
- adoption
- distribution reach
- rollout timing

Some of those drivers may be static within a month. Some may be **stateful across months**.

---

### DATA MODEL — THE SOURCE OF TRUTH

The HTML file must embed a JavaScript object named `const data = {...}`.

Every node has these fields:

| Field | Type | Applies to | Notes |
|-------|------|------------|-------|
| `id` | string | ALL | Stable, unique, snake_case |
| `label` | string | ALL | Human-readable |
| `category` | enum | ALL | One of: `profit`, `revenue`, `variable`, `fixed` |
| `type` | enum | ALL | One of: `calculated`, `input`, `ref` |
| `op` | enum or null | non-root | One of: `"×"`, `"−"`, `"÷"`, `"+"`, or `null` |
| `driver` | boolean | ALL | True if broadly shared |
| `refOf` | string or null | `type: "ref"` | Master node id |
| `formula` | string | `type: "calculated"` | Human-readable formula |
| `note` | string | optional | Context |
| `startingValue` | number | `type: "input"` | Month 1 value |
| `annualGrowth` | number | `type: "input"` | Decimal annual growth |
| `unit` | string | `type: "input"` | Unit label |
| `uncertain` | boolean | `type: "input"` | Uncertain flag |
| `children` | array | `type: "calculated"` | Recursive child list |
| `timeBehavior` | enum | ALL nodes | One of: `point_in_time`, `same_month_formula`, `stateful_roll_forward` |
| `rollForward` | object or null | `timeBehavior: "stateful_roll_forward"` | Monthly state rule, defined below |

### STATEFUL MONTHLY LOGIC

Most nodes will use:
- `timeBehavior: "point_in_time"` for input assumptions that simply grow over time
- `timeBehavior: "same_month_formula"` for calculated nodes whose monthly value is derived only from same-month children

Use `timeBehavior: "stateful_roll_forward"` only where month `n` truly depends on month `n-1`.

For stateful nodes, include:

```json
"rollForward": {
  "month1Mode": "input" | "formula",
  "month1Value": 123,
  "month1Formula": "= opening base",
  "monthlyFormula": "= prior_month + additions - churn",
  "components": {
    "priorMonth": "prior_month",
    "additions": "new_trained_providers",
    "churn": "trained_provider_churn"
  }
}
```

Guidance:
- `month1Mode` tells the downstream model how to seed Month 1
- `monthlyFormula` is human-readable only
- `components` is the machine-readable contract
- each component value must be the `id` of a child node or the special token `prior_month`

Allowed roll-forward patterns:
- `prior_month + additions`
- `prior_month + additions - churn`
- `prior_month × retention + additions`
- `prior_month + inflow - outflow`

Examples of nodes that may be stateful:
- active trained providers
- active private accounts
- cumulative facilities onboarded
- rolling tender-covered facilities
- installed base
- backlog
- inventory

Examples of nodes that should usually remain same-month:
- net price per dose
- public eligibility rate
- regional distribution cost per dose
- wage per FTE

Do **not** force everything into stateful logic. Use it only where commercially appropriate.

---

### REPEAT-AND-LINK RULE

Any node consumed by more than one parent must be repeated via `type: "ref"` and `refOf`.

This applies to:
- static inputs
- same-month calculated nodes
- stateful calculated nodes

IDs must be unique across the entire tree.

---

### CATEGORY RULES — IMPORTANT FOR EXCEL COMPATIBILITY

Use only:
- `profit`
- `revenue`
- `variable`
- `fixed`

Do not invent new categories.

---

### MARKET-ENTRY GUIDANCE

For market-entry trees:
- put demand, market size, share, penetration, onboarding, and pricing logic under `revenue`
- put unit-scaled and channel-scaled costs under `variable`
- put recurring period costs under `fixed`
- if there is rollout state, make that explicit with stateful nodes rather than hiding it in narrative text

If a launch is phased by region or channel, model the phase-in explicitly.

If launch support or training intensity is front-loaded and then declines, express that through stateful or time-phased driver nodes rather than assuming a flat monthly burden forever.

---

### OUTPUT FORMAT

Produce one self-contained HTML file:
- dark background
- monospace font
- category colour coding
- operator glyphs
- tags for `[INPUT]`, `[REF]`, `[DRIVER]`, `[?]`, and `[STATEFUL]`
- all data embedded in one `const data = {...}` object

Inline detail rules:
- `input`: `= <startingValue> <unit>, +<annualGrowth*100>% p.a.` when growth is non-zero
- `ref`: `= ↑ <master label>`
- `same_month_formula`: show `formula`
- `stateful_roll_forward`: show `month1` seed and monthly roll-forward summary

---

### WHAT TO DO WITH THE BUSINESS DESCRIPTION

Analyse the business description and:

1. Identify revenue streams and their demand / access / price logic
2. Identify variable costs and what they scale with
3. Identify fixed costs
4. Identify which nodes are truly stateful across months
5. Identify shared nodes and represent them with one master plus REFs
6. Populate every input node with `startingValue`, `annualGrowth`, `unit`, and `uncertain`
7. Populate every non-root node with `op`
8. Use `timeBehavior` on every node
9. Use `rollForward` only where stateful logic is required

### BEFORE YOU START

State briefly:
- revenue streams identified
- key stateful nodes identified by `id`
- top shared nodes by `id`
- uncertain inputs and why
- non-zero growth assumptions
- any other assumptions

Then build the tree.

### OUTPUT DISCIPLINE

Before finalising, check that:
- every node has a unique `id`
- every non-root node has an `op`
- every input has `startingValue`, `annualGrowth`, `unit`, and `uncertain`
- every node has `timeBehavior`
- every `stateful_roll_forward` node has a valid `rollForward`
- every repeated dependency is handled with `ref`
- the tree still resolves to `Net Profit = Revenue − Total Costs`
